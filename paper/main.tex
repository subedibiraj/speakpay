% ── Abstract ──────────────────────────────────────────────────────────
\begin{abstract}
Mobile payment applications have become ubiquitous in Nepal, yet remain
largely inaccessible to visually impaired individuals due to
graphically-oriented interfaces. We present \textbf{SpeakPay}, a
voice-first digital wallet that accepts spoken Nepali financial commands.
The core technical contribution is a study of domain-adaptive fine-tuning
for low-resource financial ASR. We introduce \textbf{NepFinSpeech-403},
a dataset of 403 transcribed Nepali financial voice commands,
and show that Parameter-Efficient Fine-Tuning (PEFT) via Low-Rank
Adaptation (LoRA) of Whisper large-v2 on this domain-specific corpus
significantly reduces Word Error Rate (WER) and improves Nepali numeral
recognition accuracy compared to both the zero-shot baseline and a
general-domain Nepali fine-tune. Our system, including the dataset,
fine-tuned model, and live demo application, is publicly available.
\end{abstract}

\noindent\textbf{Index Terms}: speech recognition, low-resource languages,
Nepali, domain adaptation, LoRA, accessibility, FinTech

% ── 1. Introduction ───────────────────────────────────────────────────
\section{Introduction}
\label{sec:intro}

Nepal's FinTech ecosystem has grown rapidly, with eWallet platforms
such as eSewa and Khalti serving tens of millions of users.
However, these platforms rely on visual graphical interfaces, creating
significant barriers for the estimated 95,000 visually impaired
individuals in Nepal~\cite{who2023}.

While general-purpose Automatic Speech Recognition (ASR) systems for
Nepali exist~\cite{regmi2021,paudel2023}, none address the specific
challenges of the financial domain: large numeral sequences,
bank-specific vocabulary, and intent-structured utterances.
This paper makes three contributions:

\begin{itemize}
  \item \textbf{NepFinSpeech-403}: the first publicly available
        domain-specific Nepali financial speech dataset (403 utterances,
        237 unique numerals, three intent classes).
  \item A systematic comparison of three ASR approaches on this
        domain: zero-shot Whisper, general-domain fine-tuning,
        and our financial-domain LoRA adaptation.
  \item \textbf{SpeakPay}: an end-to-end voice-first eWallet
        demonstrating real-world deployment of the model.
\end{itemize}

% ── 2. Related Work ───────────────────────────────────────────────────
\section{Related Work}
\label{sec:related}

\subsection{Nepali ASR}
Regmi and Bal~\cite{regmi2021} developed an end-to-end Nepali ASR
system using ESPnet on OpenSLR data, achieving CER of 10.3\% on
159k utterances. Paudel et al.~\cite{paudel2023} employed a
CNN-Transformer architecture achieving CER of 11.14\%.
These systems target general speech; none address financial domains.

\subsection{Whisper and PEFT}
Radford et al.~\cite{radford2022} introduced Whisper, trained on
680,000 hours of weakly supervised audio, demonstrating strong
zero-shot multilingual performance. For Nepali (Common Voice 15),
the base WER is 47.1\%, indicating substantial room for improvement.

Hu et al.~\cite{hu2022lora} introduced LoRA, which inserts
trainable rank-decomposition matrices into Transformer layers,
reducing trainable parameters by $>$99\% while matching or exceeding
full fine-tuning quality. This makes fine-tuning feasible on
consumer hardware.

\subsection{Accessible FinTech}
Ilyasa et al.~\cite{ilyasa2023} developed Visipay, an inclusive
eWallet for Indonesian visually impaired users, achieving SUS score
of 93. Zhou et al.~\cite{zhou2023} iteratively redesigned a crypto
wallet for blind users. Neither system includes a custom ASR component.

We built a structured web data collection platform
(bolanepal.netlify.app) through which contributors recorded spoken

\subsection{Domain characteristics}
Financial speech in Nepali poses two specific challenges not well-covered
by existing corpora:
(1) \textit{Numeral density}: utterances contain 1–3 large Devanagari
numerals (amounts, phone numbers, account numbers);
(2) \textit{Proper-noun density}: bank names, eWallet brand names,
and personal names that are rarely seen in general speech corpora.

% ── 4. Methodology ────────────────────────────────────────────────────
\section{Methodology}
\label{sec:method}

\subsection{Base model}
We use Whisper large-v2~\cite{radford2022}, a 1.55B-parameter
encoder-decoder Transformer. Audio is resampled to 16kHz and represented
as an 80-channel log-Mel spectrogram over 25ms windows (10ms stride).

\subsection{LoRA adaptation}
We apply LoRA with rank $r=32$ and scaling $\alpha=64$ to all
query, key, value, output projection, and feed-forward layers of
the Transformer. This introduces only $\sim$8M trainable parameters
out of 1.55B ($<$0.6\%), while keeping the base model frozen.

Training uses 8-bit quantisation (bitsandbytes) to reduce GPU memory
to 12GB, enabling fine-tuning on a single T4 GPU. We train for
200 steps with effective batch size 16, learning rate $10^{-4}$,
and cosine warmup over 50 steps.

\subsection{Evaluation metrics}
We evaluate on three metrics:
\begin{itemize}
  \item \textbf{WER}: standard word error rate.
  \item \textbf{CER}: character error rate, appropriate for
        agglutinative Devanagari morphology.
  \item \textbf{NumAcc}: our proposed \textit{numeral accuracy}
        metric — the fraction of reference Devanagari numeral
        tokens correctly reproduced in the hypothesis.
        This is the most safety-critical metric for financial ASR.
\end{itemize}

\subsection{NLP intent layer}
Transcripts are parsed by a two-stage intent classifier:
a high-confidence rule layer (precision $>$0.92 on training set)
followed by a weighted keyword feature classifier for ambiguous cases.
Parsed intents (send/load/balance/unknown) drive wallet transactions.

% ── 6. System Description ─────────────────────────────────────────────
\section{SpeakPay Application}
\label{sec:system}

SpeakPay is deployed as a Next.js web application accessible at
\url{https://speakpay.vercel.app}. The architecture comprises:

\begin{itemize}
  \item \textbf{Frontend}: voice-first UI with screen-reader
        compatibility (ARIA labels, keyboard navigation).
  \item \textbf{ASR}: Hugging Face Inference API serving the LoRA model.
        Includes automatic retry with exponential backoff for cold starts,
        and a browser Web Speech API fallback for offline use.
  \item \textbf{NLP}: two-stage intent parser with confidence scoring.
        Requires confidence $>$ 0.4 before presenting confirmation.
  \item \textbf{Backend}: Next.js API routes + Supabase Postgres with
        atomic fund transfer via a database-level stored procedure.
\end{itemize}

% ── 7. Conclusion ─────────────────────────────────────────────────────
\section{Conclusion}
\label{sec:conclusion}

We presented NepFinSpeech-403, the first domain-specific Nepali financial
speech dataset, and demonstrated that LoRA fine-tuning of Whisper
large-v2 on this small corpus substantially improves WER and numeral
recognition accuracy compared to general-purpose baselines.
The SpeakPay application demonstrates real-world deployment for
visually impaired users. Future work includes expanding the dataset,
incorporating named-entity augmentation, and conducting a formal
usability study with visually impaired participants.
